# Безопасность ValueStore

> Контракт и клиент написаны для тестовых сетей и обучения. Независимого аудита не было. Перед использованием с реальными данными или средствами нужен аудит.

## 1. Модель угроз

### Активы

| Актив | Где хранится |
|---|---|
| Строка и число | Контракт: открыто (public) или шифротекст (private) |
| Права на запись | `owner` (`Ownable`) и список редакторов (`EnumerableSet`, ≤ 32) |
| Приватный ключ кошелька | `.env` (`PRIVATE_KEY`) на машине владельца/редактора |
| Ключ шифрования AES-256 | `.env` (`VALUESTORE_KEY`) или файл вне репозитория (`VALUESTORE_KEY_FILE`) |

### Участники

- **Владелец** может всё: писать значения, управлять редакторами, передать владение.
- **Редактор** может писать и сбрасывать значения, но не может управлять редакторами и передавать владение.
- **Любой другой** (включая злоумышленника) может читать всё, что лежит в блокчейне, и отправлять любые транзакции.

### Что контракт защищает

- **Целостность значений.** Изменить или сбросить значение может только владелец или редактор (`onlyEditor` → `NotAuthorized`).
- **Управление правами.** Добавить или снять редактора и передать владение может только владелец (`onlyOwner` → `NotAuthorized`).
- **Необратимые ошибки владельца.** `renounceOwnership` отключён (`RenounceDisabled`), нулевой адрес нельзя сделать владельцем или редактором (`ZeroAddress`).
- **Неизменность режима.** `mode` хранится как `immutable`, функции чужого режима падают с `WrongMode`.
- **Раздувание хранилища.** Лимиты `MAX_STRING_BYTES = 1024`, `MAX_CIPHERTEXT_BYTES = 2048`, `MAX_EDITORS = 32`. `getEditors()` всегда ограничен 32 адресами.
- **Случайная отправка ETH.** Нет `payable`, `receive` и `fallback`, перевод ETH на контракт откатывается.
- **Поверхность атаки.** Нет `selfdestruct`, `delegatecall`, внешних вызовов, прокси и апгрейдов. Используются только `Ownable` и `EnumerableSet` из OpenZeppelin 5.6.1.

### Что контракт НЕ защищает

- **Чтение.** В блокчейне нет авторизации на чтение. Любой может вызвать `view`-функции или прочитать слоты хранилища напрямую (`eth_getStorageAt`), минуя геттеры. В режиме `public` значения видны всем. Ограничить чтение по кошельку невозможно, и контракт этого не делает.
- **Метаданные даже в `private`:** факт наличия значения (`has*`), длина шифротекста (то есть примерная длина открытого текста: шифротекст = открытый текст + 29 байт), время, автор и порядок всех изменений (события, транзакции), история всех прошлых шифротекстов в старых блоках.
- **Скомпрометированный ключ владельца/редактора.** Кто владеет приватным ключом, тот пишет. Владелец может снять скомпрометированного редактора (`removeEditor`). При компрометации ключа владельца стоит сразу передать владение (`transferOwnership`) на новый адрес.
- **Злонамеренный редактор.** Редактор может записать любое значение в пределах лимитов, в том числе мусорный «шифротекст». Контракт формат шифротекста не проверяет, клиент в этом случае выдаст `DecryptionError`.
- **Front-running и порядок транзакций.** Если два редактора пишут одновременно, побеждает транзакция, вошедшая в блок последней. Механизма блокировок нет.

## 2. Шифрование (режим private)

- AES-256-GCM на `node:crypto`, ключ 32 случайных байта, случайный IV (12 байт) на каждое шифрование, тег 16 байт.
- Формат: `0x01 | iv | ciphertext | tag`. Версия позволяет сменить формат в будущем.
- AAD `chainId:addressLowercase:field` привязывает шифротекст к сети, контракту и полю. Шифротекст из поля `string` нельзя подставить в `number`, а шифротекст из другого контракта или сети не расшифруется (`DecryptionError`).

### Ограничения шифрования

- **Один общий симметричный ключ** на контракт. Все, кто пишет и читает, знают один и тот же ключ. Отозвать доступ к уже прочитанным данным нельзя. Отзыв на будущее: новый ключ и перезапись значений.
- **Ротация ручная.** Сгенерировать новый ключ, прочитать значения старым, записать новым. **Старые шифротексты навсегда остаются в истории блокчейна** и расшифровываются старым ключом. Утечка старого ключа раскрывает все прошлые значения.
- **Потеря ключа = потеря данных.** Восстановления нет.
- **Лимит IV.** Случайный 96-битный IV безопасен для очень большого числа шифрований (порядка 2^32 на ключ), чего этот сценарий никогда не достигнет.
- **Длина не скрывается.** Паддинга нет, длина открытого текста видна.
- **Откат к старому значению.** Редактор (или владелец) может повторно записать старый, валидный шифротекст из истории. Он расшифруется. Защита от отката не входит в v1: доверие к редакторам есть часть модели.
- **Ключ на машине клиента.** Ключ хранится в `.env` или файле открытым текстом. Защита машины и файла (права 0600) на стороне пользователя.

## 3. Секреты и репозиторий

- `.env`, `.env.*` (кроме `.env.example`), `*.key`, `*.pem`, `keys/`, `secrets/`, `deployments/*.json` в `.gitignore`.
- В репозитории нет реальных ключей. В тестах используются ключи, сгенерированные на лету, и общеизвестный dev-мнемоник Hardhat (`test test ... junk`), у которого нет реальных средств.
- Деплой разрешён только в Sepolia (11155111), Hoodi (560048) и Hardhat local (31337). Mainnet и любые другие сети отклоняются скриптом деплоя и скриптами управления.
- Для `PRIVATE_KEY` используйте отдельный тестовый кошелёк без реальных средств.

## 4. Статический анализ

Дата проверки: 2026-10-19.

### solhint 6.2.5

`npm run lint:sol`, конфиг `.solhint.json` (`solhint:recommended`, `gas-custom-errors: error`, `use-natspec: warn`).

Результат: **0 ошибок, 0 предупреждений.**

Осознанные исключения:
- `immutable-vars-naming` подавлено на одной строке: имя `mode` (а не `MODE`) задано интерфейсом ТЗ (`mode()`).
- `gas-indexed-events` отключено: сигнатуры событий заданы ТЗ (`revision` не `indexed`).

### Slither 0.11.6

Установлен в виртуальное окружение Python (`pip install slither-analyzer`), запуск:

```bash
npm run slither            # = slither contracts/ValueStore.sol --config-file slither.config.json
# если solc 0.8.37 не в PATH:
slither contracts/ValueStore.sol --config-file slither.config.json --solc /path/to/solc-0.8.37
```

Результат по `ValueStore.sol` (код OpenZeppelin отфильтрован через `filter_paths`): **102 детектора, 0 находок.**

Без фильтра Slither сообщает только о коде OpenZeppelin (`Math.mulDiv`: `incorrect-exp`, `divide-before-multiply`; `assembly` в `Arrays`/`EnumerableSet`). Это известные ложные срабатывания на намеренно оптимизированный и проаудированный код библиотеки. `ValueStore` эти функции не использует, они попадают в анализ транзитивно через импорт.

### Ручная проверка

- Все внешние функции записи защищены модификаторами `onlyEditor` / `onlyOwner` (также `transferOwnership`).
- Все проверки до изменения состояния, внешних вызовов нет, поэтому реентерабельность невозможна.
- `revision` (uint256) не может переполниться на практике. При переполнении solc 0.8 откатит транзакцию.
- Компилятор: предупреждения `"at" will be promoted to keyword` относятся к `EnumerableSet.sol` OpenZeppelin, не к `ValueStore.sol`.

### Тесты

- 117 тестов (контракт, деплой, шифрование, клиент, сквозной тест через JSON-RPC).
- Покрытие `ValueStore.sol`: **100% строк и выражений** (`npm run coverage`, встроенное покрытие Hardhat 3; порог 95% проверяется `scripts/check-coverage.ts`). Ветви Hardhat 3 не считает: каждая проверка `if (...) revert` покрыта и негативным, и позитивным тестом.
